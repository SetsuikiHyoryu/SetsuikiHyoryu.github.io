# ベアリポジトリでホームディレクトリの dotfile を管理する

## ベアリポジトリとは何か

ベアリポジトリとは、`.git` ディレクトリそのものが一つのリポジトリになったものを指す  
（そのためベアリポジトリ内で直接ファイルをチェックアウトできない）。  
`--git-dir` と `--work-tree` オプションを使うと、  
両者の関連性を保ったままバージョン管理と作業ディレクトリを分離できる。

## なぜベアリポジトリを使うのか

ホームディレクトリは内容が雑多で機密情報も含むため、  
そのままリポジトリにするのは適切ではない。  
ベアリポジトリでバージョン管理と作業ディレクトリを分離すれば、  
リポジトリの境界をホームディレクトリの外に留められる。

## 設定手順

### 1. ベアリポジトリを作成する

```powershell
git init --bare ~/dotfile
```

### 2. シェルで git コマンドのエイリアスを設定する

```powershell
# $PROFILE
function dotfile {
    git --git-dir="$HOME\dotfile\" --work-tree="$HOME" -c status.showUntrackedFiles=no @args
}
```

この git コマンドは、  
指定したベアリポジトリを git リポジトリとして、  
ホームディレクトリを作業ディレクトリとして git コマンドを実行するという意味である。  
同時に、ステータスに未追跡ファイルを表示しないよう設定している。

このエイリアスでそのまま add、commit、remote、push を呼べばリポジトリを共有できる。  
なお、この状態でも `git add .` は未追跡ファイルを追加してしまうので、  
新しいファイルを追加するときはファイルパスを指定する必要がある。  
変更のみを追加する場合は `git add --update` に切り替えられる。

### 3. リポジトリから設定を同期する

#### 3.1. ベアリポジトリをクローンする

```powershell
git clone --bare <origin> $HOME/dotfile
```

#### 3.2. ファイルをチェックアウトする

```powershell
dotfile checkout
```

既存ファイルが原因で衝突した場合は、まず元のファイルを移動しておき、  
リモートと同期した上でマージするか古い内容を破棄することを勧める。

#### 3.3. リモートから更新する

```powershell
dotfile pull
```
